# Vault

个人收藏库：把看到的任何内容存进来——链接、截图、图片、音频、视频、文字——Vault 把它读懂、归好类，以后搜得到、用得上。

现在是自用阶段的网页版；数据按用户隔离、接口独立成 `/api/v1`，为以后的手机 App 留好了位置。收藏和图谱的底子来自 [SM-Intelligence](https://github.com/KewenGu/SM-Intelligence) 的收藏夹与知识图谱。

技术栈：Next.js 16 / React 19、Supabase（Postgres + pgvector、Auth、Storage）、Workflow DevKit、Claude、Voyage 向量。

## 它做什么

| 步骤 | 做什么 |
|---|---|
| 存 | 贴链接（含 App 里「复制链接」得到的那段话）、贴文字、上传 / 拖入 / 粘贴文件。同一条内容只存一次。 |
| 读取 | 链接按平台读帖子，图片和视频转存到自己的存储桶（原帖删了、链接失效了也还在）。 |
| 看和听 | 视频抽画面、测切点；视频和音频里说的话转成带时间的文字。 |
| 理解 | Claude 看图 + 读文字，产出标题、概括、内容要点（视频的带时间）、按内容类型提取的卡片字段（食材、地址、价格…）、原话、图上的文字。 |
| 思维导图 | 内容有层次时（长视频、长文、教程、盘点），理解那一步顺带整理出一份带层级的大纲，详情页画成思维导图：分支能收起 / 展开，视频的节点点了跳到那一刻，放不下时用鼠标按住拖着看（触屏上手指滑），可以全屏、可以复制成缩进的大纲贴进别的导图工具。短内容没有。 |
| 自己建导图 | 「导图」页：围绕一个主题自己建一张思维导图。页面是一个工作区：右边一整块画布是导图，左边一栏是大纲（可以收起来把地方让给图；手机上用「导图 / 大纲」切换）。在大纲里一行行写（回车加一行、Tab 缩进，手机上有按钮；贴进来好几行会按缩进变成节点），旁边的导图跟着变。右下角有个对话按钮，点开是浮在页面上的对话面板（开着也能接着改大纲；手机上从底部升起来），可以跟 AI 说话让它改图、补内容、回答问题：它看得到现在的图、图上挂着的收藏，并按你说的话去收藏库里找相关的内容；从收藏里来的节点带出处，点了回到那条内容。它改完直接生效，新出现的节点标出来，最近一次改动能撤销。新建时可以空白开始、让 AI 按主题从收藏里起草，或者在一条内容的详情页点「做成导图」。 |
| 日记 | 「日记」页：自己写的日记，一篇是一页纸，直接在上面写。能打字、放照片（选、拍，或者直接粘贴）、录一段话（浏览器里录，或者传一个录好的音频文件）；录音在后台转成带时间的文字，列在录音下面，点时间从那一句放起，点「放进正文」变成能改的一段字；点「AI 整理后放进正文」先让 Claude 去掉口头语、补标点、分好段再放进去。每一篇可以选风格（小清新 / Y2K / 卡哇伊 / 极客 / 风景：换的是纸、字体、配色、照片框，内容不动）、记心情和天气、改日期（补记）。一天可以写多篇；列表按月份往回翻，也可以看月历（写过的日子铺着那天的照片，没写过的日子点一下就补记）；能搜写过的字、照片说明和录音里说过的话。列表上面有「那年今日」：一个月前、半年前和往年的今天写过的。每一页可以存成图片（1080 像素宽的 PNG，和页面上看到的一样），手机上能直接交给系统的分享。日记不进知识图谱，也不交给 Claude 读：录音会发给语音识别；点了「AI 整理」的那一段录音的文字会发给 Claude，别的内容不发。 |
| 手帐 | 日记的每一页上还有一层手帐：贴纸（每个风格一包自带的，加一包表情，加「我的贴纸」——自己传的图片，透明底的最好，四周的空白会自动裁掉）、胶带、艺术字（五种样子）、手绘（钢笔 / 荧光笔 / 橡皮，颜色和粗细可选）。页面底下切「写字 / 贴纸 / 画笔」三种模式：贴纸能拖、能转、能放大缩小、能叠；画笔模式下一根手指画、两根手指翻页，用手写笔时手指只翻页。每一件东西挂在旁边那块正文上，正文改长了跟着走。 |
| 归类 | 内容类型（食谱 / 地点 / 商品 / 教程…15 种）、领域（美食 / 旅行 / 科技…15 个）、标签（会参考你已有的标签，尽量复用）。 |
| 目录和搜索 | 按类型、领域、来源、标签筛选；关键词 + 语义搜索，能搜到视频里说过的话和图片上的字，中英文互通。 |
| 知识图谱 | 每条内容提到的人、机构、地方、产品、作品、概念、事件增量并入一张图：同名直接归并，疑似同一个的让模型判断。 |

## 验证到了哪一步

2026-11-17，在一台云端 Linux 容器里：

- 单元测试 257 个全部通过。其中迁移脚本在本机临时起的 PostgreSQL 16 + pgvector 上实跑：行级安全、中文关键词搜索、语义搜索、筛选、图谱函数。
- 本地完整 Supabase（数据库、登录、REST、存储）+ 真实的 Claude 和 Voyage 接口，用浏览器走通：注册登录、存文字、上传截图、存网页链接、链接读不到时贴文字、重复内容去重、改标签和备注、筛选、搜索、图谱页、删除（行、文件、无主的实体一起清掉）。
- 搜索实测：搜「冰糖」找到上传的食谱截图（字在图上）；中文问句找到英文文章；英文 "pressure cooker beef stew" 找到中文食谱。
- 两个账号互相看不到对方的内容：通过页面接口、直接调 Supabase 的 REST 和存储接口都试过。

2026-11-18，在作者自己的 Mac 上（云端的 Supabase 项目、免费套餐）：一条 38 分钟、127 MB 的抖音视频走通了读取链接、下载、从原片读画面和声音、压缩副本存档，压缩后的副本能在页面上播放。提取出来的内容够不够完整还没有逐条核对过。

2026-11-19，在一台云端容器里：一个 96 MB 的真实文件下载到磁盘，进程内存涨了约 40 MB（改之前整个读进内存，同一个文件涨 350 MB）；用真实的 ffmpeg 从磁盘上的视频抽出了画面和音轨。那台容器里的 ffmpeg 是 6.1，绕过了版本检查才跑的。同一天去掉了「大视频另存一份压缩副本」这一步（上面 11-18 那条里的压缩副本是去掉之前的行为），改成原片留在服务器的磁盘上、页面从磁盘播放：这一段只跑过自动测试（搬文件、分段读取、归属检查），没有在浏览器里对着真实的大视频播过。

2026-11-20，在一台云端容器里：生产构建 + 本地模式（和 Docker 部署一样），起一个三步的测试任务，第二步跑到一半时 `kill -9` 掉服务再起来：第一步没重做，第二步重跑，第三步跑完。去掉 `src/instrumentation.ts` 做同样的事，任务停在第二步不动——之前服务器上自动更新重启后内容卡在「正在看画面」就是这个原因。用的是测试任务，不是真实的一条内容。

同一天，思维导图：详情页的导图组件用几份写好的大纲在浏览器里看过（桌面、手机宽度、暗色；收起 / 展开、全屏、复制大纲、连线跟着重画）。提示词没有用真实的 Claude 接口跑过（那台容器里没有密钥）：让另一个模型照着同样的提示词各写了一条 7 分钟的口播视频和一条一句话的备忘，前者的大纲解析出 32 个节点、3 层、6 个带时间，后者没有写大纲。没有在真实的一条内容上从存入到详情页走一遍。

2026-11-21，自己建的导图，在一台云端容器里（没有 Supabase、没有 Anthropic 的密钥）：

- 新的迁移（`maps` 表）单独在本机临时起的 PostgreSQL 16 上跑过：能重复执行；行级安全下看不到、改不了、删不了别人的图，也不能替别人插一行；默认值、`service_role` 的授权、`updated_at` 的触发器都对。带 pgvector 的完整迁移测试在那台容器里照旧跳过（装不上 pgvector）。
- 服务层用内存里的假数据库和假的 Claude 测：新建（空白 / 从一条内容）、保存、对话改图、起草、撤销、碰不到别人的图、模型失败或回答被截断时图不变且自己的改动不丢。
- 编辑器在浏览器里对着一个假后端操作过（桌面和手机宽度）：回车、Tab、退格、上下挪、工具栏、贴进多行；自动保存；点图上的节点跳到大纲里那一行、大纲光标到哪图跟到哪；对话改图后标出新节点、撤销、出错时输入的话不丢；工作区的排版（宽屏上正好一屏、大纲和画布各滚各的、收起大纲、手机上切换标签）；右下角的对话按钮（点开 / Esc 收起、开着面板改大纲、收着时 AI 在想的提示和有新回复的红点、收着时出错面板自己打开）。
- 对话的提示词没有用真实的 Claude 接口跑过。让另一个模型照着同样的提示词跑了三种：从三条材料起草（解析出 45 个节点、4 层，无关的那条没用）、只展开一个分支（原有的 6 行一字未动、顺序没变）、只问一个问题（没有改图，答的是「收藏里没找到」）。

同一天，日记本（第一期），在一台云端容器里（没有连 Supabase，没有调语音识别）：

- 新的迁移（`journal_entries`、`journal_media` 两张表）单独在本机临时起的 PostgreSQL 16 上跑过：能重复执行；行级安全下看不到、改不了、删不了别人的日记和文件，不能替别人写、也不能把文件挂到别人的日记上；带版本号的保存对不上就不写；中文按 `ilike` 搜得到；删一篇日记，文件的登记跟着删。带 pgvector 的完整迁移测试在那台容器里照旧跳过。
- 服务层用内存里的假数据库测：新建（空白的那篇不重复开）、保存（别处改过了回 409、不盖掉）、列表和搜索、前后翻、传照片 / 录音、重新转文字、删除（行和存储桶里的文件）、碰不到别人的。后台转写任务用假的 ffmpeg 和假的语音识别测：转格式、转文字、记花费、更新搜索文字；没有 ffmpeg、没配语音识别、转到一半被删掉各是什么结果。

- Chromium 录出来的 webm 确实不带时长（浏览器读出来是无穷大，拖不了进度）；用后台任务里的那两条 ffmpeg 命令转成 m4a 之后时长正常（6.24 秒）。那台容器里的 ffmpeg 是 6.1，是直接调的命令，没走应用里的版本检查。

同一天，Reddit 读取器，在一台云端容器里（没有连 Supabase）：

- 先确认了为什么要换路：Reddit 的帖子页给这台机器的是验证页，`.json` 和片段接口 403，Jina Reader 拿到的是「You've been blocked by network security」。同一台机器上第三方存档 Arctic Shift 读得到。
- 读取器对着真实的存档读了 8 条真实的帖子，各种一条：文字帖（412 条评论）、单图、图集、视频、指向 YouTube 的链接帖、转帖、被版主移除的、正文里插图的。标题、正文、作者、版块、发布时间、点赞数、评论数、图片地址和尺寸、高赞评论都读到了；每条两三秒。
- 链接帖跟着读到了那条 YouTube 视频的简介和字幕（那台容器读 YouTube 走的是 Apify）。存档里没有的 id 先按网页再试、也读不到，给出的是「存档里也还没有这一条」的提示。
- 视频：从 v.redd.it 的清单里找到了声音文件，画面（7.0 MB）和声音（0.8 MB）都下载下来，用真实的 ffmpeg 按代码里的参数合成了一个文件，探测到一条 h264 画面和一条 aac 声音、各 50.6 秒。那台容器里的 ffmpeg 是 6.1，是直接调的命令，没走应用里的版本检查。
- 那台容器直连 v.redd.it 被它自己的出网策略拦，上面这些是在 `PUBLIC_EGRESS_MODE=trusted-proxy` 下跑的；不走代理直连时图片和视频下不下得动没试。

**没有验证的**：

- Reddit：从存入到详情页走一遍（转存图片、视频合声音之后抽画面和转写、理解）；App 里「复制链接」给的短链（`/r/…/s/…`）只用假的跳转测过；家用网络下没试；存档收录一条新帖子要多久不知道。
- 「AI 整理」在真实的 Claude 上的效果：会不会改了意思、口头语去得干不干净、长的口述分段合不合适。
- 存成图片：真实的照片和「我的贴纸」（要从存储桶的签名地址跨域读，读不到的那张在图上是空的）；Safari / iPhone（这类做法在 Safari 上历来容易出问题：图片第一次画不出来、字体没嵌进去）；很长的一页（图片高度超过浏览器画布的上限时会怎样）；「分享 / 存进相册」那个按钮。
- 手帐层在真机上的手感：手指拖贴纸和转把手顺不顺、Apple Pencil 的防误触（用过笔之后手指只翻页）、iPhone 相册里抠出来的主体粘贴成贴纸、表情在不同设备上长得不一样。很多贴纸和很多笔画（几百件）时卡不卡没测过。
- 日记本在真实的 Supabase 上从新建到保存走一遍（登录、签名上传、读文件的跳转、后台任务）；真实的语音识别转一段真实的录音（准不准、中英文、带时间的句子切得合不合适）；iPhone / Android 真机上录音（Safari 录的是 mp4，没试过；锁屏、切到别的 App 时录音会不会停）、输入法、粘贴图片；两个设备同时改同一篇。
- 小红书、TikTok、Instagram、X 的真实读取。抖音只试过上面那一条。
- 思维导图在真实内容上的效果：哪些内容会有、分得好不好、节点的时间准不准。
- 自己建的导图在真实的 Supabase 和真实的 Claude 上从新建到对话走一遍；AI 改图时会不会动没让它动的地方、从收藏库里找相关内容找得准不准；手机真机上的输入法和键盘。
- 几百 MB、一两个小时的真实视频从头到尾处理一遍（下载到磁盘那一步验证过，见上；整条链路没在这么大的视频上跑过）。
- 上传的视频和音频文件（链接里的视频试过，上传的没试）。
- YouTube：从云端机房 IP 读会被要求验证（「Sign in to confirm you're not a bot」）。配了 `APIFY_TOKEN` 时自动改走 Apify（2026-11-19 在云端容器里实测：一条 15 分钟的视频约 17 秒读到标题、简介、互动数和完整字幕；拿不到视频本体，所以没有画面）。没配时的失败提示和贴文字的补救流程验证过。在家用网络下直接读应当能行，没测。
- 部署到服务器：Docker 镜像在本地构建并跑通过（见 deploy/README.md），真实服务器上还没跑过。

处理一条内容的花费（Claude Opus 5.5 + Voyage）：实测一段短文字约 $0.04，一张截图约 $0.05，一篇短文约 $0.06。带十几帧画面的视频会更高。每条的花费记在 `items.cost_usd`，详情页底部显示。想省钱可以把 `VAULT_MODEL` 换成 `claude-sonnet-5-5`。

## 本地运行

需要 Node.js 22 以上、Docker（跑本地 Supabase 用；用云端的 Supabase 项目就不需要）。

```bash
npm install
```

```bash
npx supabase start
```

`supabase start` 会自动执行 `supabase/migrations` 里的迁移。地址和密钥：

```bash
npx supabase status
```

```bash
cp .env.example .env.local
```

把 `API_URL`、`ANON_KEY`、`SERVICE_ROLE_KEY` 填进 `.env.local` 的三个 Supabase 变量，再填 `ANTHROPIC_API_KEY`（必填）和 `VOYAGE_API_KEY`（建议）。新式的 `PUBLISHABLE_KEY`（`sb_publishable_…`）和 `SECRET_KEY`（`sb_secret_…`）也能用，分别对应 anon 和 service role。然后：

```bash
npm run dev
```

打开 <http://localhost:3000>，用邮箱和密码注册（本地的 Supabase 不要求确认邮件）。

用云端的 Supabase 项目：建好项目后把迁移推上去：把迁移文件的内容贴进控制台的 SQL Editor 运行（最省事）；或者 `npx supabase link` 再 `npx supabase db push --remote`。Supabase CLI 3 起 `db push` 不带 `--remote` 推的是本机的数据库（没起 Docker 就报连不上 127.0.0.1:54322）；之前的迁移如果是在 SQL Editor 里运行的，CLI 不知道，会把所有迁移再跑一遍（迁移都写成了可以重复执行的），可以先加 `--dry-run` 看它要跑哪些，三个变量换成项目的（控制台 **Settings → API Keys**）。账号可以在 **Authentication → Users → Add user** 里直接建，勾上 Auto Confirm User 就不用等确认邮件。部署到公网时配上 `VAULT_ALLOWED_EMAILS`，或者在 Supabase 的 Auth 设置里关掉注册。

### 部署到服务器

想让它常开、手机上也能用：见 [deploy/README.md](deploy/README.md)（一台小的 Linux 服务器 + Docker + 自动 HTTPS）。Vercel 这类无服务器平台不合适：没有 ffmpeg，函数有时长和内存上限，读不了视频。

### 本机工具

| 工具 | 用来做什么 | 没有会怎样 |
|---|---|---|
| ffmpeg ≥ 8.1.3 | 抽视频画面、测切点、导音轨 | 视频只看封面和文字；上传的视频 / 音频没法理解 |
| 语音识别（豆包 / OpenAI / 本机 whisper，任一） | 把说的话转成带时间的文字 | 视频只看画面和文案；音频没法理解 |
| yt-dlp | 别的视频站、YouTube 的后备 | 这类链接只按网页读文字 |

登录后打开「状态」页（`/status`）能看到这台机器上每一项配齐了没有、缺了会怎样、怎么补。一条内容读得不完整时，详情页顶部会列出没读到的部分。

ffmpeg 的版本门槛是从 SM-Intelligence 带过来的安全基线（处理的是从网上下载的不可信文件）。macOS 上 `brew install ffmpeg` 即可；系统自带的旧版本可以用 `FFMPEG_PATH` 指到新的。

### 存档上限

视频原片和上传的文件，单个默认最多存 50 MB。这是 Supabase 免费套餐的硬上限（项目的全局上传上限封顶 50 MB）。

链接里更大的视频（最多 600 MB）照样下载下来，画面和声音从原片读。原片不进 Supabase，也不压缩，留在跑这个应用的那台机器的磁盘上（`VAULT_LOCAL_MEDIA_DIR`，Docker 部署是卷上的 `/data/media`；没设就是运行目录下的 `.vault-media`），页面直接从磁盘播放。

- 不限总量，不自动清理。「状态」页上能看到占了多少、磁盘还剩多少；剩下不到 2 GB 会提醒。
- 删掉一条内容，数据库里的行、存储桶里的文件（图片、视频、抽的帧）和这里的原片一起删。还在处理时删的，后台任务收尾时会把它后来又写出来的文件清掉。
- 只有那一台机器上有，没有备份。文件没了（清过磁盘、换了机器），这条内容读出来的画面和口播都还在，只是不能播放。
- 目录结构和存储桶一样（`<用户>/<内容 id>/video.mp4`）。以后换了付费套餐、调高上限，把这些文件搬进存储桶的功能还没做。
- 2026-11-19 之前存的大视频，存储桶里是一份压缩过的副本，照样能播。

想存更大的原片，三处都要放开，小的那个说了算：

| 哪里 | 怎么改 |
|---|---|
| Supabase 项目的全局上传上限 | 要付费套餐。控制台 **Storage → Settings → Upload file size limit** |
| 存储桶 `vault` | 迁移 `20261118000001_bucket_limit.sql` 已经设成 200 MB |
| 这个应用 | `.env.local` 里设 `VAULT_STORE_MAX_MB`（最多 200） |

「状态」页的「存档原片」一项会显示当前的上限和存储桶的上限对不对得上。另外留意总容量：免费套餐的存储一共 1 GB。

### 手机上用

网页已经适配手机宽度。在 Android 的 Chrome 里把站点「添加到主屏幕」之后，别的 App 的分享菜单里会出现 Vault，分享的链接落到确认页，点一下存入。iOS 的 Safari 不支持这个分享入口，用一个快捷指令代替：「手机」页（`/mobile`）上有按当前域名填好的步骤。从分享菜单进来存分享的内容；点主屏幕上的图标直接运行时先问「读剪贴板」还是「传照片或文件」，后者打开上传页 `/upload`（一个大按钮，点了就是系统的选照片 / 选文件 / 拍照；网页不能自己弹出选择界面，要点一下）；做好后把它的 iCloud 链接填进 `VAULT_IOS_SHORTCUT_URL`，页面上就有「安装快捷指令」按钮（快捷指令只能从苹果设备上分享出来，网站自己生成不了）。局域网里用手机访问电脑上的开发服务器时，上传的文件不会去重（浏览器只在 https 或 localhost 下提供算校验值的接口）。

服务器读不到的网页（微信公众号）用第二个快捷指令「存入 Vault（网页）」：只出现在 Safari 的分享菜单里，用「在网页上运行 JavaScript」从正在看的页面上取标题、正文、配图、发布时间，打开 `/share#page=<Base64 的 JSON>`（只对服务器读不了的站这样读，目前只有 `mp.weixin.qq.com`，名单是 `BROWSER_READ_HOSTS`；别的网站只交链接，走 `/share?b64=` 那条路），确认后存成一条链接内容，后台用这一份、不去抓网页（`src/lib/vault/page-capture.ts`）。内容放在 `#` 片段里，不发给服务器，长文不会撞上请求头的长度上限；没登录时登录完接着存。脚本也在「手机」页上，按当前域名填好。不能和普通分享的快捷指令合成一个：实测接收的类型里有网页以外的，Safari 就只交链接，脚本跑不了。还没在 iPhone 上实际跑过；很长的文章（两三万字以上）地址可能被截断，确认页会说「收到了但不完整」。

## 接口

页面和接口共用同一套逻辑（`src/lib/vault/service.ts`，导图是 `src/lib/vault/map-service.ts`，日记是 `src/lib/vault/journal-service.ts`）。鉴权认浏览器的登录态，也认 `Authorization: Bearer <Supabase 访问令牌>`。失败时返回 `{ "error": "给用户看的一句话" }`。

| 方法和路径 | 做什么 |
|---|---|
| `POST /api/v1/items` | 存一条。`{ input, note? }`，`input` 是链接、分享文案或文字。服务器读不到、客户端自己读到的网页传 `{ page: { url, title, text, description?, cover?, images?, author?, site?, publishedAt? }, note? }`（存过的同一个链接换上这份重新处理）。返回 `{ id, existing }` |
| `GET /api/v1/items` | 列出 / 搜索。`q`、`type`、`category`、`tag`、`platform`、`source`、`kind`、`entity`、`limit` |
| `GET /api/v1/items/:id` | 详情：理解结果（`understanding.outline` 是思维导图的大纲：按顺序的一行行节点 `{ depth, at, text }`，没有时是空数组）、正文、口播、文件、关联的实体 |
| `PATCH /api/v1/items/:id` | 改备注和标签。`{ note?, tags? }` |
| `DELETE /api/v1/items/:id` | 删除（连同转存的文件） |
| `POST /api/v1/items/:id/process` | 重新处理。`{ from: "fetch" \| "analyze", text? }` |
| `POST /api/v1/uploads` | 开始上传。`{ name, mime, size, sha256, note? }`，返回签名上传的 `{ bucket, path, token }`；已存过时 `upload` 为 `null` |
| `POST /api/v1/uploads/:id/complete` | 文件传完，开始处理 |
| `GET /api/v1/graph` | 整张图谱：`{ nodes, links }` |
| `GET /api/v1/maps` | 自己建的导图：`{ maps: [{ id, title, nodeCount, branches, updatedAt }] }` |
| `POST /api/v1/maps` | 新建一张。`{ title?, itemId?, draft? }`：`itemId` = 从一条内容开始（抄它的大纲、挂成来源），`draft: true` = 建好后让 AI 按标题从收藏库里起草（要等模型）。返回 `{ id }` |
| `GET /api/v1/maps/:id` | 一张图：`{ map: { title, nodes: [{ depth, text, item }], sources, chat, costUsd… }, sources: [{ id, title, origin }] }`。`item` 是节点的出处（收藏库里那条内容的 id） |
| `PATCH /api/v1/maps/:id` | 保存自己改的。`{ title?, nodes?, sources? }` |
| `DELETE /api/v1/maps/:id` | 删除 |
| `POST /api/v1/maps/:id/chat` | 跟 AI 说一句话。`{ message, title?, nodes? }`（后两个是还没保存的改动，先存下再问）；`{ draft: true }` = 起草。要等模型，一般十几秒到一分钟。返回改完之后的整张图（和 `GET` 一样） |
| `POST /api/v1/maps/:id/undo` | 撤销 AI 最近一次改的图；没有能撤销的回 409 |
| `GET /api/v1/journal` | 日记列表，日期新的在前：`{ entries: [{ id, day, title, style, mood, weather, excerpt, photos, audios, cover, updatedAt }], more }`。`q` = 搜索（空格隔开的词都出现才算），`page` = 第几页（从 0 开始，一页 60 篇）；`month` = 只要这一个月的（`YYYY-MM`，月历用，日期早的在前） |
| `GET /api/v1/journal/on-this-day` | 「那年今日」。`today` = 看的人当地的今天（`YYYY-MM-DD`，必须给）。返回 `{ items: [{ label: "1 年前", entry }] }`：一个月前、半年前和往年的同一天写过的，近的在前 |
| `POST /api/v1/journal` | 开一篇新的。`{ day, style? }`，`day` 是写的人当地的日期（`YYYY-MM-DD`，必须给：服务器不知道他在哪个时区）。这一天最后那篇还是空白的就回到它。返回 `{ id }` |
| `GET /api/v1/journal/:id` | 一篇：`{ entry: { day, title, style, mood, weather, doc: { blocks, decos, strokes }, rev… }, media: [{ id, kind, status, url, durationS, cues, notes… }], older, newer }`。`doc.blocks` 是正文：`{ id, type: "text", text }` / `{ id, type: "photo", media, caption }` / `{ id, type: "audio", media }`；`doc.decos` 是贴纸 / 胶带 / 艺术字：`{ id, kind, anchor, x, y, r, s, data }`（`kind` 和 `data`：`sticker` `{ name }` 或 `{ emoji }`、`mine` `{ sticker }`、`tape` `{ look }`、`word` `{ text, look }`；`anchor` 是挂着的那一块的 id，页眉是 `head`；`x` / `y` 是中心相对那一块左上角的位置，按 360 宽的页面算）；`doc.strokes` 是手绘的笔画：`{ id, anchor, color, width, opacity, points }`（`points` 是 x、y 交替的一串）；`cues` 是录音转出来的一句句话 `{ at, text }`；`notes` 是没做成的（没识别出说话、只转了前 60 分钟…） |
| `PATCH /api/v1/journal/:id` | 保存。`{ title?, day?, style?, mood?, weather?, doc?, rev? }`，只改给了的。`rev` 是读到这篇时的版本号：给了、而这篇在别处改过了，回 409、不盖掉。返回 `{ rev }` |
| `DELETE /api/v1/journal/:id` | 删除（连同照片和录音） |
| `GET /api/v1/journal/:id/media` | 这篇里的文件现在的样子（录音在转文字时隔几秒来看一眼） |
| `POST /api/v1/journal/:id/media` | 开始传一个文件（照片或录音）。`{ name, mime, size }`，返回 `{ media, upload: { bucket, path, token } }`；传完调下面的 `complete`，再把指着它的那一块放进 `doc.blocks` 保存 |
| `POST /api/v1/journal/:id/media/:mediaId/complete` | 文件传完。照片当场处理好；录音开始转文字。返回 `{ media }` |
| `POST /api/v1/journal/:id/media/:mediaId/retry` | 录音重新转一次文字 |
| `POST /api/v1/journal/:id/media/:mediaId/tidy` | 「AI 整理」：把这段录音的文字发给 Claude 理顺（只发这一段）。要等模型。返回 `{ text, notes }`；整理好的文字不会自己存进日记，由调用方放进 `doc.blocks` |
| `DELETE /api/v1/journal/:id/media/:mediaId` | 删一个文件 |
| `GET /api/v1/journal/stickers` | 我的贴纸：`{ stickers: [{ id, url, width, height }] }` |
| `POST /api/v1/journal/stickers` | 开始传一张贴纸（只收图片）。`{ name, mime, size }`，返回 `{ id, upload: { bucket, path, token } }`；传完调下面的 `complete` |
| `POST /api/v1/journal/stickers/:id/complete` | 贴纸传完：裁掉四周的空白、缩小、存成保留透明底的 WebP。返回 `{ sticker }` |
| `DELETE /api/v1/journal/stickers/:id` | 从我的贴纸里删一张（日记上贴着的那一件不会被拿掉，只是画不出来了） |
| `GET /media/:id/:file` | 读一个转存的文件（跳到短时效的签名地址） |
| `GET /media/journal/:mediaId` | 读日记里的一个文件（同上） |
| `GET /media/journal/sticker/:id` | 读一张我的贴纸（同上） |

## 代码结构

```
supabase/migrations/        表（items、图谱的三张、maps、日记的三张）、行级安全、搜索和图谱的数据库函数、存储桶
src/workflows/process-item.ts   一条内容的后台处理：读取 → 看和听 → 理解 → 建索引并入图
src/workflows/process-journal-audio.ts   日记里的一段录音：转成能播的格式 → 转文字
src/instrumentation.ts      服务启动时把上次没跑完的后台任务重新排上队
src/lib/
  vault/      capture（存进来的是什么）· store（items 表读写）· service（存 / 重跑 / 删）
              page-capture（在手机的 Safari 里读网页：快捷指令的脚本和确认页的解码）
              understand（提示词和解析）· outline（思维导图的大纲：解析、变成树）· taxonomy（类型、领域、实体的定义）
              自己建的导图：map-nodes（节点的形状、和模型之间的写法）· map-edit（大纲编辑器的操作）· map-store（maps 表读写）
              · map-chat（对话的提示词和解析）· map-service（新建 / 保存 / 对话 / 撤销 / 删）
              日记：journal-doc（一页的内容：正文的块、手帐层的格式、日期、搜索文字）· journal-edit（编辑器对块的操作）
              · journal-deco（手帐层的操作：贴纸、挂在哪一块上、笔画）· journal-store（三张表读写）
              · journal-service（新建 / 保存 / 搜 / 传文件 / 我的贴纸 / 删）· journal-audio（录音转成能播的格式）· journal-sticker-image（贴纸的图片处理）· journal-tidy（「AI 整理」的提示词和解析）
              speech（把说的话转成文字：收藏库和日记共用）
              indexing（搜索全文和向量文字）· search（关键词 + 语义）· facets（筛选栏计数）
  graph/      merge（实体增量并入）· data（图谱页的数据）
  ai/         claude（唯一的 Claude 调用出口）
  sources/    各平台的链接读取器
```

`src/lib/sources/reddit.ts` 是这里新写的（SM-Intelligence 那边没有），读法是从 [last30days-skill](https://github.com/mvanhorn/last30days-skill)（MIT）学来的。

和 SM-Intelligence 不一样的地方：

- 内容挂在用户上（不是人设），行级安全按用户隔离。
- 理解的提示词是通用的「讲了什么、有什么可用的信息」，不再是运营视角的「为什么火」。
- 图谱是一人一张、每存一条增量并入；那边是围绕种子整批建图。
- Claude 走官方 SDK（`@anthropic-ai/sdk`），不经 Vercel AI SDK。

## 已知的限制

- 首页一次最多列 60 条，还没有翻页。
- 中文关键词不分词：「三亚酒店」当一个词找，要拆开搜得写成「三亚 酒店」；语义搜索那一路会补上一部分。
- 语义搜索的相似度门槛（0.35）和实体归并的门槛（0.76）还没有用大一点的真实数据校准。
- 口播最多转写前 60 分钟。链接里的视频最多下载 600 MB 来读（`VAULT_VIDEO_READ_MAX_MB` 可改）：下载到磁盘上的临时目录，读完就删，不进内存。超过存档上限（默认 50 MB）的原片不进 Supabase，留在服务器的磁盘上（见「存档上限」）：磁盘只会越用越多，要自己看着清；上传的文件不走这条路，超过上限的传不上来。
- 上传的图片会统一成 JPEG（长边最多 2160），不保留原文件。长图（高是宽的 1.8 倍以上：手机截图、长截图、小红书长图）按宽度缩，宽最多 1440、高最多 3 万像素；给模型看时缩到宽 1024、切成每段 1536 高的几段（单张最多 16 段，一条最多 40 段，没给模型看的部分记进「没看到」）。2026-11-19 之前存的长图已经按长边缩小了，原图没留，要重新上传才清楚。iPhone 的 HEIC 照片在浏览器里一般会自动转成 JPEG 再传，转不了的会提示。
- Reddit 是从第三方存档 Arctic Shift 读的，不是从 Reddit 读的：
  - 点赞数、评论数、每条评论的赞数是存档记下的那一刻的（详情页的「读取情况」里写着是发帖后多久记的），之后涨了多少不知道；刚发的帖子存档里可能还没有，读取会失败，过一阵再重试。存档停了或改了接口，这条路就断了。
  - 评论最多读存档里的 500 条，留赞数最高的 12 条（回复也算），每条给模型看前 600 字；评论搜不到，页面上也不显示。
  - 投票的选项和票数不读；动图只存静止的画面；浏览量、转发数没有。被移除的帖子能读到存档里留下的内容。
  - 版块主页、用户主页、wiki 的链接读不了（以前按网页读，机房 IP 上也读不到）。以前按「网页」存过的 Reddit 链接不会自动换成新的读法，要重新贴一次链接。
- 不支持 PDF 和 Office 文档。
- 图谱里并错的实体还不能手动拆开或合并。
- 详情页上一条内容的思维导图只能看，不能改（要改：点「做成导图」，抄一份到自己的导图里改）；有没有由模型按内容有没有层次决定，没有手动「给这条生成一张」的按钮。2026-11-20 之前处理的内容没有大纲，点详情页底部的「重新分析」才会有（按一次理解的花费算）。
- 日记本：
  - 搜索只按字面找（没有语义搜索），和收藏库的搜索是分开的；艺术字上的字搜不到。
  - 月历不带月份打开时，开的是服务器那边的当月（按 UTC 算）：月初月末那几个小时可能和你那边差一个月，点一下箭头就到。月历上一天有好几篇时只铺第一张照片。
  - 「那年今日」只找一个月前、半年前和往年的同一天；那个月没有这一天的（3 月 31 日的一个月前）不拿邻近的日子顶替。
  - 存成图片是在浏览器里画的（把页面画进一张 SVG 再转成 PNG），一次一页；录音在图上是一个条和前 8 句话。没有导出成 PDF、一次导出好几篇。
  - 手帐层：
    - 写字、贴纸、画笔是三种模式，要在底下那一栏切：写字时碰不到贴纸，贴纸模式下改不了字。
    - 贴纸和笔画没有撤销 / 重做，只有画笔的「撤销一笔」（去掉最后画的那一笔，包括以前画的）；橡皮是整笔擦，不能只擦一段。
    - 一件东西挂在一块正文上：那一块上面的字改长了它跟着往下走，但那一块自己的字改了、换了行，它不会跟着某一个字走。换风格、换字体后每行的字数会变，贴在字旁边的东西可能就不在原来那几个字旁边了。
    - 自带的贴纸一共 28 张，是自己画的简单图形；艺术字只有五种样子，用的是已有的字体，没有专门的书法 / 美术字体。
    - 表情贴纸用的是设备自己的表情字体，在不同的手机和电脑上长得不一样。
    - 「我的贴纸」最多 200 张，存成长边不超过 512 像素的 WebP；从里面删掉一张，已经贴在日记上的也看不到了（不会提示哪几篇用过它）。不会自动抠图：要透明底得自己先抠好。
    - 一页最多 300 件贴纸、600 笔。
  - 正文是纯文字，没有加粗、标题这类格式。照片和录音放在光标所在的那一块文字后面，不会把一段字从中间拆开。
  - 一页固定 360 宽、按屏幕等比缩放（为了以后贴纸的位置在手机和电脑上对得上）：电脑上看字比较大，一行十八九个字。
  - 录音最长 60 分钟，录的时候数据在浏览器的内存里：录完之前关页面、刷新，这一段就没了。麦克风只在 https 或 localhost 下能用。录音转文字要这台机器有 ffmpeg 和语音识别（见「本机工具」），没有时录音照样存、能播，页面上说明没转成的原因，可以点「重新转文字」。
  - 录音会发给配的那家语音识别（豆包 / OpenAI），除非只用本机的 whisper。日记的文字和照片不发给任何模型，只有一个例外：点了一段录音下面的「AI 整理后放进正文」，那一段录音的文字会发给 Claude。
  - 「AI 整理」一次最多整理两万字（大约一小时的口述），再长的只整理前面的；整理出来的可能和你说的有出入，放进正文后自己看一遍。花费记在那段录音上（`journal_media.cost_usd`，页面上还没有显示）。
  - 上传的照片会统一成 JPEG（长边最多 2160），不保留原文件；一篇最多 60 个文件。存储用的是同一个存储桶（免费套餐一共 1 GB）。
  - 「小清新」和「卡哇伊」的字体（霞鹜文楷 Lite、站酷快乐体，都是 OFL 许可）打包在应用里，按用到的字分片加载；另外三种风格用设备自带的字体，不同设备上看起来会有差别。风格只有这五种，还不能自己调纸和配色。
  - 换风格只是换这一篇的；新开的一篇接着用最近动过的那一篇的风格。
- 自己建的导图：
  - 只能在大纲里改，不能在图上直接拖节点、改字。一张图最多 300 个节点、6 层。
  - AI 每次是把整张图重写一遍（提示词里要求没让动的原样留着，但不保证）：改完看一眼标出来的节点，不对就撤销。只能撤销最近一次；撤销会连同那之后自己手动改的一起回去。
  - AI 在想的时候大纲锁住，回答不是一个字一个字出来的，要等十几秒到一分钟。
  - 给一张图加收藏只有两条路：AI 用到了哪条就自动挂上，或者从那条内容的详情页「做成导图」新建；还不能在导图页里手动挑一条收藏挂上去。
  - 两个设备同时改同一张图，后保存的盖掉先保存的。
